# dsh-llm-pi-gateway 兼容性测试

## 定位

gateway 不禁用或接管官方 `llm-pi-ai`。官方插件保持 provider 注册、设置节和模型发现；gateway 不注册 adapter、directory 或 discovery。它依据 `llm.directory` 中官方 namespace 的 directory 条目，以条目 `provider` 字段作为 route key（而非 Map key）检索 adapter registration，并核对 registration `provider.id`。仅当 adapter 原型提供 `streamWithSnapshot` 时才装饰；Models 可装饰时才构造 snapshot facade。owner 只对 sweep 中获授权的 adapter 实例生效，不同原型共享 Models 时也各自绑定实例 owner。DSH `0.2.0-rc.2` 的目标为官方 PiAiAdapter。

directory route 移除后，后续 sweep 不会立即撤销已授权实例的 owner；授权持续到 gateway dispose 或 reapply 清理失活 owner。测试覆盖 route 移除边界，注册表授权语义按实例生命周期而非每轮全量重算。

只将 Anthropic `streamSimple` options 注入派生的 `metadata.user_id`；其他协议透传。

## 测试

| 层 | 命令 | 断言 |
| --- | --- | --- |
| 单元 | 在包目录运行 `npm test` | marker 派生、Anthropic 注入、OpenAI 透传、原 options 不变、同实例 owner 切换、同 Models 实例复用、跨原型共享 Models、同原型跨 namespace 实例隔离 |
| 仓库加载 | 仓库根运行 `node scripts/smoke-load.mjs` | 仓库插件入口均可导入 |
| 隔离端到端 | 仓库根运行下方 compat 命令 | profile 仅加载 gateway；seed echo provider 注册、OpenAI 与 Anthropic 当前 turn 的 fixture 文本已渲染（UI roundtrip）、`/messages` 上游请求和 Anthropic 派生 marker 均进入阻塞判定；activation 全 live 且无 findings；不证明协议流完整终止 |

```sh
node scripts/compat/run.mjs --version 0.2.0-rc.2 --host-dir .compat/0.2.0-rc.2/dsh-host --work-root .compat/gateway-0.7.2-final-validation --only dsh-llm-pi-gateway --seed-gateway
```

该 compat 命令必须从仓库根执行。它操作仓库内 `.compat` 隔离数据，不读取或修改 `~/.dsh` 真实 profile，不重启真实宿主。

Compat runner 启动 echo simulator 时显式使用 compat 专用 `--echo-user-message`；它仅在 default OpenAI/Anthropic 路径的流式和非流式回复中附带可用于当前轮判定的 user 文本。公共 CLI 默认、Responses、think/tool 场景仍使用固定 fixture 内容。

- activation `liveAll=true` 且 `findingsCount=0`。
- seed echo provider 注册、双协议当前 user 对应的 fixture 文本已渲染（UI roundtrip）、composer 清空且 UI error/alert 文案为空；该断言不证明协议流完整终止。echo-upstream 协议单测仅验证模拟器成功响应发出协议终止事件，不代表宿主消费端已观测终态。DOM 当前没有稳定跨协议终态信号，因此完整 delta 后的连接异常中断可能仍通过 UI 断言。
- 上游留档同时含 `/chat/completions` 与 `/messages` 请求。
- Anthropic `/messages` 请求体 `metadata.user_id` 匹配 `dsh:<40 位小写十六进制>`；缺失/错误 marker 会令 full compat 失败。
- browser probe 页面文案满足工作区可见且不含插件加载失败横幅。compat 通过判定不以留档中的 `consoleErrors` 或 `httpFailures` 为空为条件；这两项仅用于诊断。

- 完整 compat 的 `ok` 要求页面可达、activation 全 live 且无 findings、LLM 双协议发送操作及当前 turn assistant-step fixture 文本已渲染（UI roundtrip）、两协议 composer 清空且 UI error/alert 文案为空、上游路由留档及 Anthropic marker 有效、无行级加载失败。此断言不证明协议流完整终止；`consoleErrors` 与 `httpFailures` 仅供诊断。


### owner 切换

`test/decorator.test.mjs` 的 owner 用例覆盖实例授权边界、同一实例 owner 切换与生命周期：非官方实例即使共享同一原型也不得继承官方 owner；旧 owner 失活后重新授权同一实例，由新 owner 注入；同一实例重复 sweep 不重复添加 owner。测试验证稳定原型 wrapper 与 Models facade 的可观察注入结果，不模拟 Cordis `apply`、fiber 清理回调或 `llm/adapters-updated` 宿主事件装配。
