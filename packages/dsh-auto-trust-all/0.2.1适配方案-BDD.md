# dsh-auto-trust-all 双代适配方案(BDD,审核修正版)

> 本文档是实施输入,面向零上下文执行 AI。动手前必读:仓库根 `AGENTS.md`、`DEVELOPMENT/structure-and-release.md`(hostMin/发布流程)、`DEVELOPMENT/dsh-api-alignment.md`(安全边界)。本任务:同一插件版本覆盖 0.2.0-rc.2 与 0.2.1-alpha.2 两代宿主,**禁止顺手重构现有语义**;按宿主版本维护两套实现被明确否决。

## 背景:宿主 0.2.1-alpha.2 的破坏性变更(双闭包源码实证)

证据基座:`.compat/0.2.1-alpha.2/dsh-host/node_modules/`(隔离闭包);对照 0.2.0-rc.2 闭包 `C:/Users/yuanhao/AppData/Roaming/nvm/v24.14.1/node_modules/@deepseek-ai/dsh/`。

1. **`webRuntime` 服务面消失**:alpha 闭包零命中 `webRuntime`(0.2.0 由 `dsh-web-app` 提供,经官方 patch 供 `connection` 行作启动配置);alpha 的 `connection` 行改读 `webStartup.trustedHosts`。本包旧实现以 `webRuntime.trustedHosts` 在场为注册门槛 → alpha 上永不就绪。
2. **webserver 拒通配绑定**:alpha `WebServer.Config.host` 必填、只收单个具体 IP 字面量;官方 patch 自带 `127.0.0.1` 兜底,无 `--host` 正常回环启动。0.2.0 线 schema 只收 `127.0.0.1`/`0.0.0.0`,但其 CLI 显式拒绝 `--host 0.0.0.0`(startup.js)。
3. **`--trusted-host` 静态旗标两代均有**(非 alpha 新增):条目为 `host:port` 精确或 `host` 匹配任意端口;绑定地址 authority 天然被信任;fence 对每请求实时判定。

## 关键事实(审核修正,替代早期误判)

- **fence 在 route.handler 内**(两代同构:connection 的 `/api` prefix handler 先 `admit` 再桥接),本包包装在委托原 handler 前完成注册 → **首次直接 `/api` 请求即可学习 Host,无需先访问页面**;LRU 淘汰条目重访即恢复(旧 README「淘汰后重启前不可达」的说法已证伪并修正)。
- **`connection.trustedHosts` 是两代共同的可变数组形态**(构造入参直存、每请求实时 `.some()` 读),运行时 push 即时生效;但两代 `.d.ts` 均声明 `private readonly`——**共同内部形态,非官方稳定公开契约**,必须形态探测,不得宣传稳定 API。
- **`allowsRemoteAuthorities` 非 API 闸门但有消费者**:alpha `dsh-host-directory-picker-auto` 在 boot 时读它选 native/browse 目录选择器;构造时凝固,运行时 push 不更新。回环反代部署需部署层显式选择,本包不改该属性(早期「零消费」判断错误)。
- `webRuntime` 的宿主内请求相关消费仅 0.2.0 官方 patch 克隆进 `connection` 配置;本包镜像它只为已公布的 dream-skin 等同构自守卫插件共存语义,不是闸门。

## 用户部署场景(需求来源)

- **绿联 NAS Docker + 官方免费穿透**:穿透送达形态未取证(透传域名 / 改写 loopback / 改写容器 IP);动态信任覆盖全部三态,N1 真机如实记录。
- **公司 nginx 反代多子域名 → 内网 PC**:子域可增,动态信任是刚需(stock 静态清单每加一个子域要改启动项重启)。
- Docker 容器 IP 漂移 → bind 由部署层运行时解析(entrypoint `--host "$(hostname -i)"` 或等价);本包不碰 bind 面。

## BDD 场景

### 单元(test/,夹具注入,零宿主;场景号见测试文件)

- **U1(场景38)** 单 fence 形态全流程:仅 connection 在场,注册/淘汰/卸载在主数组成立,evicted 日志输出,无 webRuntime 依赖与等待噪音。
- **U2(场景1/22)** 双写形态不回归:两数组在场时注册写入两者(镜像语义)。
- **U3(场景4/16/33)** LRU 与归属清理在单 fence 成立:淘汰主数组条目并输出日志,卸载清理本代条目。
- **U4(场景3b/11)** loopback 不注册(官方恒放行,登记零增益)。
- **U5(场景10)** patch v2 形态锁:仅 insert op,无 webserver 覆盖、无 `0.0.0.0` 字样;`package.json` 的 `dsh.hostMin = "0.2.0-rc.2"`,双代际在 dshReleases。
- **时序(场景18/19/24/30/31)** connection 延迟激活、等待行一次、webRuntime 先就绪不激活不写任何目标、webRuntime 等事件不激活、未就绪卸载不复活。
- **换代与守卫(场景14/40/41)** 主/镜像数组换代回填且归属延续、LRU 不清空;(场景39)冻结数组告警停用。

### 闭包真机(`.compat/<版本>`,run.mjs/boot-keep.mjs 同款隔离;两代各跑一轮)

- **R1(双代)** 隔离 boot + 横幅:出现 `动态信任已启用 (bind ..., 容量 100), ..., 镜像 webRuntime 在场/缺席`(alpha=缺席、rc.2=在场);无 `connection 未就绪` 等待行;activation live、findings 0。
- **R2(双代)** 首个直接 `/api` 学习:伪造 Host + 同源 Origin 打 market 读端点 → 200 + registered 日志;随后同 Host 打 `/api`(无 cookie)→ **401 unauthorized**(fence 放行、认证拒绝——证明注册先于 fence,非 403)。
- **R3(双代)** 原生拦截不动:伪造 Host + 异源 Origin 打 `/api` → 403(fence 同源检查);`sec-fetch-site: cross-site` → 403;loopback Host 不产生 registered 行。
- **R4(双代)** 缺省绑定不崩:无 `--host` 启动 → 按 stock 回环正常启动(本包不再覆盖 bind);显式 `--host` 后横幅随实际绑定变化。
- **R5(双代)** 容量淘汰自愈:patch 行级 `maxHosts: 2` 热重载 → 第三域名触发 evicted 日志;被淘汰域名重访 → registered 重现。

### NAS 真机(用户配合,升级后执行)

- **N1 穿透链路端到端**:绿联 docker + 穿透域名打开页面并发一轮对话;全程 200/无 403;`docker logs` 可见 `registered host <穿透送达的 Host>`(域名/loopback/容器 IP 三态如实记录)。
- **N2 Origin 透传型穿透的硬化风险点**:穿透改写 Host 但透传 Origin → 按 fence 语义 403;属宿主 fence 与穿透形态不兼容,处置 = 绿联侧透传 Host 或部署层静态 `--trusted-host`,不是本插件可修。**两代 fence 语义相同,回退 0.2.0 不能缓解此形态**(早期方案该判断错误,已修正)。
