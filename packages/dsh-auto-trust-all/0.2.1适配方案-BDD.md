# dsh-auto-trust-all 0.2.1 线适配方案(BDD)

> 本文档是实施输入,面向零上下文执行 AI。动手前必读:仓库根 `AGENTS.md`、`DEVELOPMENT/structure-and-release.md`(hostMin/发布流程)、`DEVELOPMENT/dsh-api-alignment.md`(安全边界)。本包 0.2.0 线行为已在生产验证,**禁止顺手重构现有语义**;本任务只做下述适配。

## 背景:宿主 0.2.1-alpha.2 的三项破坏性变更(全部已实证)

证据基座:`.compat/0.2.1-alpha.2/dsh-host/node_modules/`(隔离闭包,已装好);对照 0.2.0-rc.2 生产闭包 `C:/Users/yuanhao/AppData/Roaming/nvm/v24.14.1/node_modules/@deepseek-ai/dsh/`。

1. **`@deepseek-ai/dsh-web-runtime` 服务面消失**:alpha 闭包字符级零命中 `webRuntime`(0.2.0 的 `dsh-web-app/lib/index.js:30,175` 是提供方 `ctx.provide("webRuntime", runtime)`);alpha 改 `webServer` 链(`dsh-web-app/lib/index.js` 的 `inject = ["webServer"]`)。本插件 `registerHost` 首行以 `ctx.get('webRuntime')?.trustedHosts` 数组在场为注册门槛 → alpha 上永不就绪(真机日志 `webRuntime 未就绪,待其激活后自动启用`)。
2. **webserver 拒通配绑定**:alpha `dsh-host-webserver/lib/index.js` 的 `WebServer.Config.host` 为必填、只收单个具体 IP 字面量(`0.0.0.0`/`::` 及主机名均抛错)。本包 patch 的 `host: !!js ctx.webStartup.host ?? '0.0.0.0'` 兜底在 alpha 上不传 `--host` 时必崩(实证:闭包冷启动 `webserver (required) ... wildcard address ... not supported`)。
3. **新增 stock `--trusted-host` 旗标**(静态信任清单):条目为 `host:port`(精确)或 `host`(匹配任意端口);绑定地址 authority 天然被信任;fence 对每请求实时判定。

## 关键事实:适配通路已存在,改动面很小

alpha 的 `/api` 信任闸门 = `dsh-client-connection/lib/index.js` 的 `isTrustedApiRequest(request, trustedHosts, bindHost)`(`requestRejection` 先 fence 403 后 auth 401):

- 放行条件:loopback hostname ∨ `trustedHosts` 条目 ∨ 绑定地址 authority;`sec-fetch-site: cross-site` 拒;带 Origin 时必须与 Host 同 authority(HTTPS 默认端口归一化已处理)。
- **`trustedHosts` 是 connection 服务上可变的数组引用,fence 每请求实时 `.some()` 读它**——运行时 push 即时生效。
- **本插件已有 `syncFence`**(src/index.js):`ctx.get('connection')?.trustedHosts` 存在即 push(带 `fenceAdded` 归属去重、`removeFromFence` 只撤自己推入的条目)。0.2.0 线生产已验证该双写语义。
- `allowsRemoteAuthorities`(connection 服务属性,构造时凝固)**在 alpha 闭包零消费**,不构成隐藏闸门,无需处理。

因此 alpha 上缺口只有一个:**注册门槛挂在 webRuntime 上**。connection 服务在 alpha 存在(服务名 `connection`,`HostConnectionService` 构造第二参 `super(ctx, "connection")`,属性 `trustedHosts`)。

## 用户部署场景(需求来源,方案必须同时覆盖)

- **绿联 NAS Docker + 官方免费穿透**:无公网,域名 `app-45903-dajuzi.cn73.ugdocker.link`(绿联分配,固定值);穿透送达 dsh 的 Host/Origin 形态未取证(透传域名 / 改写 loopback / 改写容器 IP,三态矩阵见下「部署配方」)。
- **公司 nginx 反代多子域名 → 内网 PC**:子域可增,**动态信任是刚需**(stock 静态清单每加一个子域要改启动项重启)。
- Docker 容器 IP 重启漂移 → bind 必须运行时解析(entrypoint `--host "$(hostname -i)"`)或穿透落 loopback;**本插件在 0.2.1 线不碰 bind 面**(见已定决策 D2)。

## 已定决策表

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 适配 vs 退役 | **适配**,发 v2 形态 | 多子域动态信任是 stock 静态清单覆盖不了的真实需求(用户场景二) |
| D2 | bind 兜底(patch 覆盖 webserver 行) | **v2 patch 删除该 op**,bind 责任归部署层 | alpha 拒通配且 host 必填;插件自动解析 IP 会引入 DHCP/容器漂移故障面,为省一个 `--host` 旗标不值 |
| D3 | 版本策略 | **新版本声明 `dsh.hostMin: 0.2.1-alpha.2`**;0.2.0 线用户停留现有已发布版(0.3.1),装载层按 hostMin 自动排除 | 复用仓库自身机制,不做双线分支;遵守「不留向后兼容层」 |
| D4 | 注册目标 | **双目标注册**:任一目标(webRuntime 数组 / connection fence 数组)在场即工作;两端都在场时维持现有双写 | 0.2.0 双写语义已验证;alpha 单 fence 语义由同一段代码自然覆盖 |
| D5 | 就绪判定与日志 | 就绪 = 任一目标数组在场;alpha 上不再输出「webRuntime 未就绪」等待行,改为就绪时打印 `bind 信息 + 注册目标形态` | 现等待行在 alpha 是永真噪音 |
| D6 | 安全边界 | 只做「加信任」,不碰同源比对 / sec-fetch-site / 认证层 | AGENTS.md 安全边界约定;伪造 Host 仍须 403(BDD-07) |

## BDD 场景

### 单元(test/,夹具注入,零宿主)

**场景 U1:alpha 单 fence 形态注册**
- Given 夹具 ctx 仅有 `connection.trustedHosts = []`(无 webRuntime),插件激活
- When 到达请求 Host = `a.example.com`
- Then `connection.trustedHosts` 含 `a.example.com`,console 输出 `registered host a.example.com`,无 webRuntime 等待行

**场景 U2:0.2.0 双写形态不回归**
- Given 夹具 ctx 同时有 `webRuntime.trustedHosts = []` 与 `connection.trustedHosts = []`
- When 到达请求 Host = `a.example.com`
- Then 两个数组都含 `a.example.com`(现有行为逐字保持)

**场景 U3:LRU 与归属清理在单 fence 形态成立**
- Given U1 形态,`maxHosts = 1`
- When 依次到达 `a.example.com`、`b.example.com`
- Then `a.example.com` 被 `connection.trustedHosts` 移除并输出 evicted 行,`b.example.com` 在列;插件卸载后 `b.example.com` 被移除

**场景 U4:loopback 不注册**
- Given U1 形态
- When 到达 Host = `localhost` / `127.0.0.1:9291`
- Then fence 数组不含 loopback 条目(官方恒放行,登记零增益)

**场景 U5:patch v2 形态锁**
- Given 发布物 `cordis.patch.yml`
- Then 不含 `id: webserver` 覆盖 op(全文件无 `0.0.0.0` 字样),仅保留插件插入 op;`package.json` 的 `dsh.hostMin = "0.2.1-alpha.2"`

### 闭包真机(`.compat/0.2.1-alpha.2`,run.mjs 同款隔离环境;web 半区探针按仓库 browser-probe 惯例)

**场景 R1:alpha 隔离 boot + 注册时序**
- Given v2 插件装载,`dsh web --no-open --port 9291 --host 10.123.60.41`(隔离 home,冷启动清 sessions)
- When 浏览器首访页面(未带任何静态 `--trusted-host`)
- Then 页面渲染后同 authority 的 `/api` 请求 200,过程中无 403 先行(index/静态请求先完成注册——fence 与路由 wrap 的先后顺序是本场景的核心断言)

**场景 R2:多 authority 逐个注册**
- When 依次以 `Host: a.example.com`、`Host: b.example.com`(带对应 cookie 与 Origin)发 /api 请求
- Then 首个请求 403(fence 拒,未注册)、页面类请求触发注册后 /api 200;`connection.trustedHosts` 含两个条目

**场景 R3:伪造 Host 仍拒**
- When 带合法 cookie、`Host: evil.example.com` 打 /api
- Then 403(本插件不旁路 fence 的同源/跨站检查)

**场景 R4:bind 缺省不崩**
- When `dsh web --no-open --port 9291`(无 --host,v2 patch 不覆盖 webserver)
- Then 按 alpha stock 默认行为启动(host 必填时的 stock 报错形态需如实记录,不属于本插件缺陷面);显式 `--host` 后全链正常

### NAS 真机(用户配合,升级 0.2.1 后执行)

**场景 N1:穿透链路端到端**
- Given 绿联 docker 部署 + 穿透域名 `app-45903-dajuzi.cn73.ugdocker.link`
- When 外网浏览器经穿透域名打开页面并发一轮对话
- Then 全程 200/无 403;`docker logs` 可见 `registered host <穿透送达的 Host>`(形态三选一:域名/loopback/容器 IP,如实记录)

**场景 N2:Origin 透传型穿透的硬化风险点**
- Given 穿透改写 Host 但透传 Origin(浏览器 `Origin: https://app-….ugdocker.link` 与改写后 Host 不同 authority)
- When POST /api
- Then 按 alpha fence 语义将 403——**若发生,属宿主 fence 与穿透形态不兼容,登记宿主差异,处置 = 要么绿联侧透传 Host,要么回退 0.2.0 线,不是本插件可修**

## 实施步骤(文件:位置 + 改什么)

1. `src/index.js`:
   - `registerHost` 首行门槛改为双目标探测:`webRuntime.trustedHosts` 与 `connection.trustedHosts`,任一数组在场即继续;仅对在场目标 push(`syncFence` 已有 connection 侧逻辑,复用);两端都在场时保持现有双写次序。
   - `ready()` 与 15s 等待行:就绪 = 任一目标在场;就绪日志改为输出注册目标形态与当前 bind(从 `ctx.webServer?.host` 读)。
   - 淘汰/卸载清理(`removeFromHosts`/`removeFromFence`)双目标幂等,现逻辑基本复用,补单 fence 形态分支。
   - `inject = ['webServer']` 不变;注释更新(webRuntime 字样改为「跨版本基座服务 + 按代际存在性探测」)。
2. `cordis.patch.yml`:删除 `id: webserver` 覆盖 op(含头注释同步改写),保留插件插入 op。
3. `package.json`:加 `dsh.hostMin: "0.2.1-alpha.2"`;`dsh.compatibility.dshReleases` 增 `0.2.1-alpha.2: "待真机"`(真机通过后改 `compatible`);版本号按 `DEVELOPMENT/structure-and-release.md` 流程递进(publish 唯一入口)。
4. `test/patch.test.mjs`、`test/wrap.test.mjs`:按 U1–U5 增改(现测试即夹具式,沿用其注入手法)。
5. README「dsh 版本兼容」节 + `兼容性测试.md`:按仓库动态窗口口径重写(v2 形态声明:0.2.1 线纯动态信任、不碰 bind;0.2.0 线用户留 0.3.1)。
