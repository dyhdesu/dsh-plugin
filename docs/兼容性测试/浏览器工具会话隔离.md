# 浏览器工具会话隔离测试

## 目的与适用范围

验证 `tool_search` 只搜索调用会话可见的定义，浏览器 lazy 工具只在调用 agent 的作用域中逐批注册。A 搜索或使用浏览器工具后，B 与新会话 C 的工具列表不得随之改变。

本协议是浏览器隔离补丁的专项回归，不替代全仓兼容性测试。宿主固定为 `0.2.1-rc.2`，浏览器包固定为 `dsh-browser-cdp@1.6.0`；升级任一版本时须重新核对宿主 API、补丁与预期工具批次。

## 前置条件与隔离

- Node.js >=22、Git 在 PATH 中；仓库根能解析 Playwright。Playwright 仅使用 HTTP request context，不启动浏览器。
- 指定已安装的宿主包目录，目录包含宿主入口及依赖闭包；不在本流程升级或替换宿主。
- 原版及修复浏览器包分别放在隔离工位，不能用生产安装包承载补丁实验。
- 源码测试需要上游仓库及其开发依赖。上游提交、原版入口和修复入口以补丁清单为身份依据；不能只校验版本号。
- 每次完整宿主实验自动新建临时 home/profile、随机端口和独立 echo-upstream。禁止复用长驻 echo、发送真实 LLM 请求、修改生产 profile 或重启生产宿主。

以下命令从本仓库根执行，使用 Git Bash/POSIX shell 语法。将三个目录替换为实际隔离工位路径；路径允许使用 Windows 的 `C:/...` 格式。`BROWSER_SOURCE` 是已按源码补丁修改并安装开发依赖的上游仓库；`ORIGINAL_BROWSER` 是未修改的发布包副本：

```sh
export TOOL_SYNC_HOST='/absolute/path/to/@deepseek-ai/dsh'
export BROWSER_SOURCE='/absolute/path/to/dsh-browser-cdp-source'
export ORIGINAL_BROWSER='/absolute/path/to/original-dsh-browser-cdp'
```

源码来自 [dsh-browser-cdp 上游仓库](https://github.com/drscrewdriver/dsh-browser-cdp)。在本仓库根执行以下准备命令；`BROWSER_SOURCE` 必须是尚不存在的新目录。`upstreamCommit` 从清单读取，不使用上游最新分支：

```sh
export PATCH_FILE="$(pwd)/scripts/patches/browser-session-scope/source.patch"
export UPSTREAM_COMMIT="$(node --input-type=module -e 'import fs from "node:fs";console.log(JSON.parse(fs.readFileSync("scripts/patches/browser-session-scope/manifest.json")).upstreamCommit)')"
git clone https://github.com/drscrewdriver/dsh-browser-cdp.git "$BROWSER_SOURCE"
git -C "$BROWSER_SOURCE" switch --detach "$UPSTREAM_COMMIT"
git -C "$BROWSER_SOURCE" apply --check "$PATCH_FILE"
git -C "$BROWSER_SOURCE" apply "$PATCH_FILE"
npm --prefix "$BROWSER_SOURCE" install --ignore-scripts --legacy-peer-deps --no-audit --no-fund
```

依赖安装使用上游开发依赖；`--legacy-peer-deps` 避免历史宿主 peer 范围妨碍独立源码测试，不改变完整宿主实验所用的宿主闭包。预期源码差异仅为 `src/index.ts`、`src/toolTiers.ts`、`tests/tier-mount.test.ts`；依赖安装生成的锁文件不属于补丁。

## 执行流程

按顺序执行，任一步非预期失败即停止后续验收并定位。

### 源码与工具门回归

```sh
npm --prefix "$BROWSER_SOURCE" test
npm --prefix "$BROWSER_SOURCE" run typecheck
npm --prefix "$BROWSER_SOURCE" run build
node --test "packages/dsh-tool-gate/test/*.test.mjs"
```

验收条件：测试无失败；宿主和客户端类型检查、构建均退出 0。记录实际通过数、跳过数及原因，不将历史用例数当作门槛。上游登录导入、远端 CDP、Lightpanda、CLI 和渲染探针的显式环境开关未启用时，应明确记为未覆盖；不要为消除跳过而操作真实登录数据。

源码挂载测试须覆盖：独立 agent 注册及批次状态、agent 退场、插件卸载、lazy/always 切换、无 agent 调用、不同注册对象的 `deferLoading` 变异隔离。工具门回归须覆盖兄弟会话、同名局部定义、restrict 隐藏项以及搜索前后 schemas/defer 状态不变。

### 原版失败对照

首次验证补丁、修改隔离实现或升级适用版本时执行。普通文档修改不要求重跑失败对照。

先确认原版入口 SHA-256 等于清单 `originalSha256`，然后执行：

```sh
TOOL_SYNC_BROWSER="$ORIGINAL_BROWSER" node scripts/diagnostics/tool-sync-live.mjs --assert-isolated
```

预期是非零退出，错误必须是“A调用doctor改变了B的实际tools数组”，且证据中的 `cleanupOk` 为 true。启动失败、依赖缺失、超时或其他断言失败均不能作为有效的失败对照。

### 修复构建与发布包产物

源码构建入口 `lib/index.js` 的 SHA-256 须与清单 `patchedSha256` 一致；不一致时先调查构建或补丁漂移，不自动更新清单。

复制原版发布包到另一个可写隔离目录，然后应用运行时补丁。以下变量不能指向原版对照目录或生产包：

```sh
export PATCHED_BROWSER='/absolute/path/to/patched-dsh-browser-cdp'
node scripts/diagnostics/apply-browser-scope-patch.mjs "$PATCHED_BROWSER"
```

验收条件：输出 SHA 与清单一致，原入口备份存在且匹配 `originalSha256`。再执行同一命令应输出“补丁已应用，无需改写”，不再新增备份。应用器遇到陌生包版本或入口 SHA 应拒绝覆盖。

### 完整宿主有门与无门

```sh
TOOL_SYNC_BROWSER="$PATCHED_BROWSER" node scripts/diagnostics/tool-sync-live.mjs --assert-isolated
TOOL_SYNC_BROWSER="$PATCHED_BROWSER" node scripts/diagnostics/tool-sync-live.mjs --assert-isolated --without-gate
```

两种环境分别冷启动。仅 LLM 回复由 echo 模拟，浏览器插件、工具执行体、宿主派发和持久化均走实际实现。

| 场景 | 必须满足的断言 |
|---|---|
| 冷启动 | 浏览器常驻工具精确为 doctor/help/navigate/script/snapshot/space/status 七项 |
| A 只搜索 doctor（有门） | B 整个上游 tools 数组与基线相等，无 tool-addition 通知 |
| A 实际调用 doctor | A 解锁至 24 项；B 整个 tools 数组不变，无新增通知 |
| A 再调用两次 help | A 为 28、29 项；第二批新增 js/page_info/read_element/screenshot，第三批仅 wait |
| B 未使用浏览器 | B 整个 tools 数组仍与基线相等 |
| 新建 C | C 整个 tools 数组与基线相等，浏览器工具为七项 |
| B 自己首次调用 help | B 从第一批开始，为 24 项；A 整个 tools 数组保持不变 |

每次必须同时满足：进程退出码 0；输出证据中的 `result.isolated`、`ok`、`cleanupOk` 均为 true；两次 cleanup 记录的 `running` 和 `occupied` 均为空。比较实际 tools 数组及批次成员，不能只比较总数。

## 结果与工件

脚本打印本轮临时工位及证据位置。验收时检查本轮证据 JSON、宿主日志和 echo 请求记录；核对隔离副本入口 SHA-256 与补丁清单一致。

报告至少包含：宿主/浏览器/工具门版本、源码提交及入口 SHA、执行命令、退出码、通过/跳过/失败数、两种环境的场景断言、清理结果、未覆盖项。工件可能含进程访问令牌及请求内容，不能直接提交 Git。

退出码非零、`ok: false` 或资源未释放均判失败。跳过与环境阻塞独立报告，不能写成“全部正常”。真实页面操作、原生 DeepSeek 服务端激活以及其他插件健康状况不在此专项覆盖范围。

## 安装与运行中生效

补丁将 lazy 状态和注册放在调用 `exec.agent.ctx`，每次注册克隆定义；根作用域保留常驻工具，显式 always 模式仍全局开放。补丁未发布到 npm，重新安装原版包会覆盖本地修改。

安装属于部署操作，应与上述隔离测试分开。确认目标包身份后才使用应用脚本；脚本只替换磁盘入口并备份，不修改 profile 或重启宿主。`runtimeReloaded: false` 不是运行中生效证据，刷新网页也不会清除宿主模块缓存。

需要运行中生效时，由宿主插件管理重载目标插件，检查操作成功及最终 enabled/active 状态。记录重载警告并分别处理；不得据插件 active 或磁盘 SHA 推断所有行为测试通过。自动化验收不得为此切换生产插件。
