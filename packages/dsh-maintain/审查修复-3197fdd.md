## 已定决策

| 决策项 | 选择 | 理由 |
|---|---|---|
| 版本读取失败语义 | 插件干净继续运行、版本未知 | 符合兼容规约;版本监测失败不能拖垮宿主插件加载。 |
| Windows回滚状态 | 依据激活操作最终链接目标核验 | 只在旧链接最终未恢复时保留锁,避免一次性创建故障制造永久误锁。 |
| 跨平台测试 | 原语按host OS执行,平台专用格式化断言按OS跳过 | POSIX根路径和真实PATH语义不能伪装为Win32。 |
| 验收布局 | npm global prefix 完全置于随机临时根 | 满足平台真实global目录布局与入口生成,不使用用户全局prefix。 |
| 验收超时清理 | 不确定则保留目录并输出诊断路径 | 不与仍存活的lifecycle后代竞态删除。 |
| npm发现 | 已知文件系统路径白名单,不执行shell探测 | 兼容系统npm同时维持可审计的可执行入口。 |

## 实施与验证记录

实现已完成,代码改动覆盖 R1–R6;产品级受管升级保持关闭,不把回归原语或脚本冒烟宣称为宿主健康验收。

- R1: `resolveCurrentHostVersion()` 同步 realpath/read/JSON 解析纳入 try/catch,失败返回 null(未知版本);新增缺失安装锚点与损坏清单两条挂载回归。
- R2: `switchLink` win32 失败分支就地恢复旧 junction 并按 `linkMatches` 实测置位;`activateInstallation` 外层按最终链接目标核验,恢复成功时清除标记。故障注入经新增 `symlinkImpl` 参数进入真实 switchLink 路径,仅注入一次。
- R3: managed-layout / managed-upgrade 夹具按 `process.platform` 构造 prefix 布局与命令入口;APPDATA 断言与链接类型按平台分流;新增 POSIX 槽位边界用例。

- R5: 脚本以受控 spawn 跟踪子进程,超时即 `preserveRoot` 置位并 taskkill/进程组 SIGKILL;finally 仅在无不确定状态时清理,失败打印保留路径;SIGINT/SIGTERM 终止在跑子进程。
- R6: `findNpmCli` 候选扩展 `../share/nodejs/npm/bin/npm-cli.js` 与 `../share/npm/bin/npm-cli.js`,各配临时树测试。
